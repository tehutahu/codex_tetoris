# BLOCK SPRINT

10列×20行の盤面で、20ラインを消すまでの時間に挑戦する一人用ブロックゲームです。CanvasとDOMで描画し、ゲーム規則を独立したJavaScriptモジュールで検証します。対戦通信・ログインはありません。

## 起動

Node.js **20.19以上の20系**（`.nvmrc`）とnpmを使います。リポジトリのルートで実行してください。Windows PowerShellで `npm` が実行ポリシーにより拒否される場合は `npm.cmd` を使います。

```sh
npm ci
npm run dev
```

[http://127.0.0.1:5173](http://127.0.0.1:5173) を開きます。開発はViteだけで動きます。5173番が使用中ならエラーで終了します。`Ctrl+C` で停止します。

ビルド済み成果物をローカルで配信する場合は次を実行します。

```sh
npm run build
npm start
```

[http://localhost:3000](http://localhost:3000) を開きます。`npm start` は `client/dist` を配信し、再ビルドしません。ソースを変えたら再ビルドしてください。`PORT` 環境変数で配信ポートを変更できます。

POSIX環境の初期セットアップは `bash scripts/codex-setup.sh` でも実行できます。Dockerは採用しません。

## 遊び方

スタートすると800msごとにピースが落下します。7種類を各1回ずつ出す7-bag、次の3個の表示、着地点のガイドを使い、横一列を埋めて消します。20ラインでクリア、次のピースが出現できなくなるとゲーム終了です。

| 操作 | キー |
| --- | --- |
| 開始・終了後に再開 | Enter |
| 左右移動 | ← / → |
| 右回転 / 左回転 | ↑ または X・W / Z・Q |
| ソフトドロップ | ↓ |
| ハードドロップ | Space |
| 一時停止・続ける | P / Esc |
| 同じ順番でやり直す | R |

画面ボタンでも操作できます。タブの切り替えや画面からフォーカスが離れると自動停止します。初期状態と停止中は時間が進みません。

URLの `?seed=任意の文字列` を共有すると同じ出現順になります。再開は同じseedで盤面・時間・得点をリセットします。得点は1〜4行消去で100/300/500/800点、手動落下は1マスにつきソフト1点・ハード2点です。

横移動は押した直後に1回、180ms後から55ms間隔で反復します。ソフトドロップは直後に1回、以後45ms間隔です。キーボードと画面ボタンで同じ規則を使います。回転とハードドロップは押下ごとに1回です。

回転は水平の壁キックだけです。接地から300ms後に固定し、接地中の成功した移動・回転で猶予を延長できるのは1ピース8回までです。ハードドロップは即固定します。ホールド、T-spin特別得点、速度上昇、標準SRSは採用していません。詳細と判断理由は [ゲーム仕様](docs/game-design.md) にあります。

## 検証

```sh
npm test
npm run build
npm audit --audit-level=high
npx playwright install chromium
npm run test:browser
```

`npm test` はNode標準テストランナーで本番のゲーム規則・controller・HTTP配信を検証し、失敗時は非0を返します。`test:browser` はビルド済み成果物を一時ポートで配信して実Chromiumで操作します。合法なキー入力で20ライン達成・ゲームオーバー・再開まで確認し、画面とレポートを `output/playwright/` に保存します。テスト終了時にブラウザとサーバーを閉じます。

PRのCIはクリーンなUbuntu / Node 20で導入・実テスト・ビルド・依存監査・Chromium検証を実行し、スクリーンショットをartifactへ保存します。実測結果と未検証範囲は [受け入れ記録](docs/acceptance.md) を参照してください。

## 構成と範囲

本番ゲームはブラウザの標準機能、配信はNode標準HTTPを使います。ViteとPlaywrightは開発用です。「オフライン」は、初回にHTMLとassetを取得した後、ゲーム進行が通信に依存しないことを指します。PWA・ネット切断後の新規起動・データ保存・ランキング・公開デプロイは対象外です。Chromiumで検証しています。実機のタッチ操作、Safari、Firefoxは未検証です。

[文書の入口](docs/README.md) に構成と設計理由をまとめています。エージェントがゲームルールとアーキテクチャを自由に選ぶ方針は `AGENTS.md` と [管理Issue #21](https://github.com/tehutahu/codex_tetoris/issues/21) が入口です。課題と進捗はGitHub Issues/PRを正本とし、文書に進捗チェックリストは複製しません。
