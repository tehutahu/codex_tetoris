# BLOCK SPRINT のゲーム設計

## 選んだ完成形と理由

BLOCK SPRINTは、1人で20ライン消去を目指す短いスプリントです。既存のテトリス型の操作を活かし、目標と終了条件を明確にしました。通信がなくても遊べる構成に絞り、ゲーム規則はブラウザから独立したJavaScriptモジュールとして検証します。標準仕様の網羅より、操作・終了・再開がつながる小さな完成形を優先しました。

描画はCanvas、画面・操作説明・ボタンはvanilla DOMを使います。React、Phaser、Socket.IOによるゲーム描画や通信は使いません。新しい本番依存はありません。依存・サーバー・配布方法の整理はIssue #19、実ブラウザを含む最終受け入れはIssue #20で扱います。進捗の正本はGitHub IssuesとPRです。

## 規則

| 項目 | 採用した仕様 |
| --- | --- |
| 盤面 | 10列×20行。見えない行は設けない |
| 目標 | 消去したラインが20以上になるとクリア |
| ピース | I / J / L / O / S / T / Zの7種類 |
| 出現順 | seedに基づく7-bag。各袋に7種類が1個ずつ入る |
| NEXT | 次の3個を上から順に描画 |
| ゴースト | 移動・回転後のハードドロップ着地点を枠で描画 |
| 出現位置 | 行0、ピース行列を水平方向に中央配置 |
| 回転 | 正方行列の90度回転。候補の水平移動は0、−1、+1、−2、+2列の順。上下移動はしない。Oは回転で変わらない |
| 自然落下 | 800msごとに1行。レベルによる加速はない |
| 固定 | 接地から300ms。接地中の成功した移動・回転で300msへ戻すのは1ピース8回まで。失敗・Oの回転・softDropでは戻さない。ハードドロップは即固定 |
| 行消去 | 固定後、最上段を含む全行を判定。埋まった行を除き、その上に空行を補充 |
| 固定後の順序 | 固定 → 行消去・加点 → 20ライン達成判定 → 次のピース出現・衝突判定 |
| ゲーム終了 | 行消去後でも次の出現位置が固定ブロックと衝突する場合 |
| 再開 | 同じseedの初期盤面、ピース順、得点、ライン数、時間へ戻して開始 |
| 停止 | 一時停止・開始前・クリア後・ゲーム終了後は時計と落下が停止。ウィンドウのフォーカス喪失・タブ非表示も一時停止 |

得点は、1回の固定で消したライン数が1/2/3/4なら100/300/500/800点です。ソフトドロップで実際に動いた1行ごとに1点、ハードドロップで動いた1行ごとに2点を加算します。自然落下は加点しません。クリア時間はプレイ中の時間を0.1秒単位で表示し、終了した重力ステップより後の余剰時間を計上しません。

水平キックはSRSではありません。ホールド、T-spin、コンボ、レベル、対戦、音楽は採用しません。旧12列盤面と無期限プレイは、見やすい10列盤面と20ラインの終了目標へ置き換えました。NEXTを表示しない旧処理や対戦盤面は削除しています。

## 操作

| キー | 動作 |
| --- | --- |
| ← / → | 即時1回、180ms後から55ms間隔で反復 |
| ↑ / X / W | 右回転 |
| Z / Q | 左回転 |
| ↓ | 即時1回、以後45ms間隔で反復 |
| Space | ハードドロップ |
| P / Esc | 一時停止・続ける |
| Enter | 開始・一時停止から続ける・終了後に同じseedで再開 |
| R | 同じseedでやり直す |

画面の開始・一時停止・再開ボタンも使えます。画面下のボタンとキーは同じ反復時計を使い、OSのキーリピートは無視します。回転とハードドロップは保持中に反復しません。開始・再開時は盤面へフォーカスを移します。

左右同時押しは最後に押した方向を優先します。優先方向を解除すると、残った方向の180ms待機を新たに開始し、解除直後には移動しません。同じ操作をキーとpointerで保持しても二重反復しません。複数pointerはIDごとに解除し、異なる操作を併用できます。pointerup・cancel・capture喪失・ボタン外への移動で解除します。pause・blur・タブ非表示・終了・restartはすべての保持を解除し、続けるには改めて押します。

規則識別子は `sprint-20-lock300-v1` です。接地は下の1行へ進めなくなった瞬間に始まり、描画頻度には依存しません。移動で空中へ戻った間は残る猶予を停止します。延長上限後に空中へ戻っても猶予はリセットせず、再接地後に残りだけを数えます。入力反復と自然落下・固定を時系列で処理し、同じ時刻では固定の期限を入力より先に判定します。300msは置く直前の調整を可能にし、延長8回は固定を際限なく先延ばししないための選択です。従来の即固定とは記録の条件が異なるため、#29の保存記録はこの識別子で分離します。

## 再現と構成

URLの`?seed=任意の文字列`でピース順を指定できます。指定しなければ新しいseedを作り、URLと画面へ表示します。例: `http://localhost:3000/?seed=acceptance-20`。URLを保存し「同じ順番でやり直す」を使うと、同じ初期状態から練習できます。seedで再現するのはピース順です。結果まで再現するには入力と時間も一致させます。

- `client/src/game.js`: `createGame(seed)`、`updateGame(state, action)`、衝突・回転・行消去・ゴースト。DOM、時計API、描画、通信に依存しない。各操作は新しい状態を返し、以前の状態を変更しない。
- `client/src/controller.js`: 入力前に時計を同期し、純粋なゲーム規則へ渡す。`dispatch(type)`、`tick(timestamp)`、コピーを返す`getState()`を公開。逆順のtimestampは時間を巻き戻さない。
- `client/src/input.js`: 描画・DOMに依存しない保持入力と反復予定。controllerは `press(source, action)`・`release(source)`・`clearInput()`を公開し、描画間に反復予定があってもその時刻まで規則を進めてから入力する。
- `client/src/main.js`: Canvas描画、DOM、日本語状態表示、キーボード・画面ボタン、タブ非表示時の停止。ゲーム規則の別実装や検証専用の盤面変更機能は持たない。
- `client/src/styles.css`: デスクトップと小画面のレイアウト。

ゲーム状態は`ready`、`playing`、`paused`、`won`、`lost`の5種類です。純粋な入力には`start`、`pause`、`restart`、`moveLeft`、`moveRight`、`rotateLeft`、`rotateRight`、`softDrop`、`hardDrop`、`tick`（`deltaMs`）を使います。`main.js`がexportする`controller`も、実画面で使われている同じインスタンスです。`getState()`の変更はゲームに反映されません。

## 検証の境界

`tests/game.test.js`は、ブラウザと同じ生産モジュールをNode.js 20から直接読み込みます。盤面とNEXT、4袋分の7-bagとseed、左右端・床・固定ブロックの衝突、左右回転・水平キック・失敗した回転、最上段と複数行の消去、固定位置とゴースト、得点、消去前の出現誤判定、終了・達成・再開、800ms境界と余剰時間、ポーズ、snapshotの保護を検証します。旧実装で起き得た「出現判定を行消去より先にする」「最上段を消さない」を明示的な回帰として含めます。

基本コマンドは`npm test`と`npm run build`です。ゲーム規則だけを確認する場合は`node --test tests/game.test.js`を使えます。実ブラウザではキーボードと画面ボタンによる操作、行消去、20ライン達成、出現衝突での終了、同じseedでの再開、デスクトップとモバイル幅を確認します。固定seedの合法な入力から終了まで進める受け入れ手順をIssue #20で記録します。実端末のタッチ操作や、すべてのブラウザでの同一挙動は自動検証から推定しません。
## 完走記録と再挑戦

保存先はlocalStorageの `block-sprint.records.v1:sprint-20-lock300-v1`。schema版1と規則識別子で比較条件を分離し、完走時だけseed・ミリ秒に丸めた時間・得点・ISO日時を保存します。比較は時間だけを使い、同タイムは更新しません。得点は補助です。全体ベストは出現順をまたぐ練習記録であり、同じ条件の競技ランキングではありません。

seed別ベストは改善された順に128件まで保存し、上限では最も古いものを除きます。全体ベストを別枠で残すのでseed別の削除でも失いません。完走への状態遷移で1回保存し、lost・pause・restart・描画更新では保存しません。不正JSON、不正な値、未知schema・規則、重複seed、比較矛盾は読み捨てます。読み書き拒否・容量エラーは表示して画面内の比較とゲームを継続します。

同じ順番の再挑戦はseedを保って初期化し、新しい順番は異なるseedを生成してURL・画面・盤面・得点・時間・保持入力を更新します。削除はプレイ中ならpauseし、確認またはキャンセルでき、現在の規則の記録だけを消します。保存の扱いは `client/src/records.js` と独立テストで検証します。新規本番依存はありません。
