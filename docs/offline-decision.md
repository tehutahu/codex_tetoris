# オフライン構成を選んだ理由

2026-10-04、管理Issue #21の自由な再設計方針とIssue #19の採否判断に基づき、対戦を採用せず、1人で20ライン到達を目指すスプリントに統一した。

## 遊び方と構成

1つの盤面で開始から成功またはゲームオーバーまで完結し、同じ画面から再挑戦する。ゲームルールは描画や通信に依存しないJavaScript、表示はCanvasとHTML、開発・ビルドはVite、配信はNode.js標準HTTPを使う。ゲーム中の対戦通信・外部ランタイムCDN・アカウント・ランキングは不要である。

ここでいう「オフライン」はゲーム進行がブラウザ内で完結する意味である。最初のHTMLと資産は開発サーバーまたは静的配信サーバーから取得する。PWAのキャッシュや、通信が切れた状態からの新規起動は今回の仕様に含めない。

## 判断の理由

旧サーバーは受け取った盤面を他の全接続へ転送していた。相手や試合が固定されず、3人以上の接続では相手表示を上書きし、開始・終了・切断・再戦も1つの試合として成立していなかった。これを完成するには通信制限、相手の隔離、勝敗、切断対応など、1人のゲームには不要な状態と運用が増える。

小さな終了目標を持つスプリントなら相手の接続を待たずに遊べ、ルールを固定入力で再現して検証できる。React / Phaser / Express / Socket.IOを維持する必要もなくなり、描画、純粋なルール、静的配信の境界が明確になる。新しい本番依存を追加せず、Viteを開発依存として残す。開発時も通信APIを使わないため、npm run devはViteだけを起動し、Node HTTPとの二重起動スクリプトとproxyを削除した。

## 配信の仕様

- npm run build が client/dist を生成する。npm start は事前ビルド済みの成果物を配信し、起動時にビルドしない。成果物がない場合は必要なコマンドを表示して終了する。
- createGameServer({ staticDirectory }) はポートを開かず { server } を返す。テストはこの本番のfactoryを使い、仮の別サーバーを再実装しない。
- GET / と GET /index.html は入口を配信する。存在する資産を拡張子に対応するMIMEとバイト長で返し、HEAD は同じヘッダーと空の本文を返す。
- 資産、ディレクトリ、未知の画面URLが見つからなければ404を返す。SPAの入口へフォールバックしない。旧 /socket.io/ 入口も存在しない。
- GET / HEAD以外は405と Allow: GET, HEAD を返す。
- URLの不正なエンコードとnull文字は400、ドット始まりのパス要素、Windowsの区切り文字、代替データストリームの指定、配信ディレクトリ外への参照は403で拒否する。実パスも確認し、外部を指すシンボリックリンク／junction経由の配信を防ぐ。
- キャッシュの再確認を要求し、MIMEの推測を禁止する。ゲーム状態を送信・保存するAPIは持たない。

## 検証の入口

tests/server.test.js はNode.js標準テストランナーと本番HTTPサーバーを使用し、HTML、JS / CSS / SVG、未知拡張子、クエリ、HEAD、404、405、不正URL、パストラバーサル、外部junctionを確認する。HTTPリクエストに生のパスを渡し、ブラウザやURLライブラリが .. を正規化して防御テストを無効にすることを避ける。

ゲームルールと画面の確認方法はゲーム側の仕様書と受け入れ検証文書を参照する。最終的なコマンド、CI、実ブラウザの結果は関連PRに記録する。進捗の正本はGitHub IssuesとPRであり、この文書に進捗チェックリストを複製しない。

## 実装時の検証

Node.js 20.20.2でnpm CLIを直接起動し、npm ci、npm test（配信10テスト）、npm audit、npm audit --omit=devを実行した。すべて成功し、auditの脆弱性は開発依存を含め0件だった。指定PORTが数値でない場合と、ビルド成果物がない場合のCLIは、理由を表示して終了コード1を返すことも確認した。

依存整理後のlockfileは223エントリから68エントリへ減り、rootとclientの本番依存は空になった。Issue #18のゲーム画面を統合した後も、Node.js 20.20.2でnpm ci、npm test（全32テスト）、npm run build、npm auditが成功した。生成したJSは14.32 kB、CSSは8.35 kBである。標準HTTPからPlaywrightの実ChromiumへHTMLとJS / CSSを配信し、3リクエストとも200、consoleのerror / warningは0、外部接続は0だった。資産読み込み後にブラウザの通信を切り、開始、ハードドロップ、一時停止、同じseedからの再開と得点リセットを確認し、スクリーンショットを保存した。最終CIと20ライン達成・ゲームオーバーの統合受け入れ結果は関連PRで確認する。
